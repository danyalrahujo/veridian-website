Case Study — Finance

Real-time fraud detection at a national bank

A streaming anomaly-detection model reduced fraud losses by 42% while cutting the false-positive rate that had been overwhelming the manual review team.

FinanceFraud DetectionStreaming ML
The Challenge

Rules-based detection couldn't keep pace

The bank's existing fraud system relied on static rule thresholds that fraud rings routinely worked around within weeks of any update. Manual review queues had grown to the point where genuine fraud cases were taking days to catch, while false positives were frustrating legitimate customers and consuming analyst capacity.

Our Approach

A streaming model with a human-reviewed escalation tier

We built a real-time anomaly-detection model scoring every transaction as it streamed through the payment platform, tuned against a cost-weighted objective that balanced fraud loss against false-positive review cost, with a tiered escalation path for borderline cases.

Architecture

How it's built

DG
Kafka transaction stream → feature service → real-time scoring model → tiered routing (auto-clear / auto-block / human review) → feedback loop into retraining pipeline.

Implementation

An 11-week rollout

Wks 1-2

Discovery & baseline

Quantified the existing false-positive rate and fraud loss baseline against which the new model would be measured.

Wks 3-6

Model development

Built and validated the scoring model against a cost-weighted evaluation objective, not raw accuracy.

Wks 7-9

Shadow deployment

Ran the model alongside the existing rules engine without acting on its output, to validate live performance.

Wks 10-11

Phased cutover

Gradually shifted decisioning traffic to the new model with monitoring at each stage.
